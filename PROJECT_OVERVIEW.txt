# Zero-Coupling Signal Router (zcsr) — 项目结构说明

## 一句话定位
纯 C11、零运行时堆、跨平台、模块化的轻量游戏中间件/引擎。目标是抛弃旧系统兼容包袱，为 2026 年后的新平台（Windows 10+ / macOS 15+ / 最新 Android）做顶级性能的 2D 游戏地基。3D（zcsr_3d）在规划中。

## 核心设计原则（硬约束）
1. **零耦合**：每个模块只 include 共享契约头 `include/zcsr/*.h`，禁止 include 其他模块的 .c 或相对路径。vendored 依赖（glad/stb）只能在所属模块内用。
2. **无运行时堆**：模块状态全放在调用方提供的 buffer 里（`void* buffer, size_t bytes`），不 malloc/calloc/free。不透明句柄 + C 原型 = 稳定 ABI。
3. **固定池**：对象数量上限编译期确定，状态在静态/外部 buffer 里预分配。
4. **确定性**：不依赖隐式全局状态，同输入同输出（为回放/联网同步设计）。
5. **纯 C**：C11，不依赖 C++ STL/异常/RTTI。C ABI 稳定，可被任何语言/引擎嵌入。
6. **平台 hook 隔离**：平台差异（窗口/GL上下文/音频/输入）通过 6 个平台 hook 函数隔离，公共逻辑三平台共享。

## 构建系统
- CMake 3.16+，C11
- 每个模块通过 `zcsr_module(name)` 函数编译成静态库
- 测试两层：`tests/`（每模块单元测试 + ctest，headless）；`integration/`（demo + bench，需真实 GPU/音频）
- 耦合守卫脚本 `tools/check_no_cross_includes.sh`：扫描 modules/ 下所有 .c/.m/.h，禁止 include `../` 或 `modules/` 开头（third_party 除外）

## 关键技术决策
1. **GL 渲染**：OpenGL 3.3 Core，vendored glad 运行时加载函数指针。Windows 需要临时 legacy context 才能查 wglCreateContextAttribsARB。
2. **音频混音**：固定池（1 个 mixer 实例），命令环形缓冲（128 条），完成环形缓冲（128 条），独立音频线程，无堆分配。
3. **2D性能优化【已完成】**：纹理图集 + 实例化渲染(glDrawArraysInstanced) + 视口剔除(线性/均匀网格) + 状态排序(不透明合批/半透明画家算法)。10000 sprite 在 Release 下 0.62ms，raylib 6.0 对比 0.76ms。
4. **内存安全**：大结构体清零用 memset（避免复合字面量在栈上创建多 MB 临时对象导致栈溢出）。
5. **跨平台计时**：Windows 用 QueryPerformanceCounter，POSIX 用 clock_gettime。

## 与现有开源方案的区别
- vs SDL2：SDL2 是纯平台层工具箱（窗口/输入/音频/计时），本项目额外提供游戏逻辑层（信号路由、HSM、确定性混音）
- vs raylib：raylib 有堆分配、单一大库、不是零耦合；本项目模块间完全解耦、无堆、caller buffer
- vs Godot/Unity：本项目是中间件/库，不是完整引擎，无编辑器、无物理、无网络
- vs Photon Quantum：Quantum 是商业 Unity 插件，本项目是纯 C 可嵌入任何宿主
