## 一、项目是什么（30秒版）

**Zero-Coupling Signal Router (zcsr)**：纯 C11、零运行时堆、跨平台、模块化的 2D 游戏引擎中间件。

**核心设计约束（从第一天就定的硬约束，不是事后优化）：**
1. 零耦合：每个模块只 include 共享契约头 `include/zcsr/*.h`，模块间不互相 include
2. 无运行时堆：模块状态全放调用方提供的 buffer（`void* buffer, size_t bytes`），不 malloc/free
3. 固定池：对象数量上限编译期确定
4. 确定性：同输入同输出（为回放/联网同步设计）
5. C ABI 稳定：可被任何语言/引擎嵌入
6. 抛弃旧系统兼容：只支持 Windows 10+ / macOS 15+ / 最新 Android，不支持 XP/Win7 等

**当前规模**：13 个模块，20 个契约头，Windows 全量构建通过（14/14 ctest 绿），Release 性能 10000 同纹理 sprite = 0.6ms。

## 三、当前核心困境（这是我需要你帮我决策的）

### 困境本质

我付出了以下**代价**：
- 抛弃了旧系统兼容（不支持 XP/Win7/旧 macOS）
- 零耦合（开发约束更严，模块间不能直接调用）
- 无运行时堆（不能 malloc，所有状态放调用方 buffer）

**我期望这些代价换来"绝对性能榨取"的回报**——即在 2D 游戏引擎这个赛道，我的引擎在引擎层性能上应该比 SDL2/raylib 这类项目强，因为我没有历史包袱。

**但目前的现实是**：我只做了 2.5/9 项引擎层性能技术，性能数据只测了最优情况（同纹理 sprite），没测最坏情况（不同纹理、混合状态、大规模实例化）。

### 我目前的引擎层性能技术清单（已做 vs 未做）

| 技术 | 引擎层还是游戏层 | 我做了吗 | 说明 |
|---|---|---|---|
| 运行时零分配 | 引擎层 | ✅ 已做 | 无 malloc/free 抖动 |
| 固定池 | 引擎层 | ✅ 已做 | 预分配 |
| 相邻同纹理 draw call 合并 | 引擎层 | ⚠️ 做了一半 | 只合并相邻同纹理，不做全局排序 |
| 实例化渲染（instanced rendering） | 引擎层 | ❌ 没做 | 一次 draw call 画 N 个 sprite |
| 纹理图集（texture atlas） | 引擎层 | ❌ 没做 | 多小纹理合并成大纹理 |
| 状态排序（state sorting） | 引擎层 | ❌ 没做 | 按纹理/blend/shader 排序减少状态切换 |
| 多线程渲染 | 引擎层 | ❌ 没做 | 游戏线程和渲染线程分离 |
| GPU 内存池 | 引擎层 | ❌ 没做 | 顶点缓冲/索引缓冲复用 |
| 视口剔除 | 引擎层 | ❌ 没做 | 2D 视口外 sprite 不提交 |
| SIMD CPU 计算 | 引擎层 | ❌ 没做 | 用编译器内置，不手写汇编 |

### 我的性能数据（只有最优情况）

- 200 sprite（同纹理）：0.19ms
- 1000 sprite（同纹理）：0.16ms
- 10000 sprite（同纹理）：0.60ms
- **未测**：10000 sprite（不同纹理）、10000 sprite（混合 blend mode）、100000 sprite

### 我对自己项目的判断（可能有错，请你推翻）

1. ECS、线程池、AI、物理——这些是**游戏层**的事，不是引擎层的事。引擎不应该内置 ECS，开发者自己在游戏层定义。
2. 引擎层性能应该和 SDL2/raylib 直接对比，而且必须碾压它们，否则我付出的代价没有回报。
3. 我目前的 0.6ms/10000 sprite 是"够用"但不是"顶级"——因为没测最坏情况，没做实例化/图集/排序。
4. 我不应该追求 3A 3D 渲染（那是几百人团队的事），但在 2D 引擎赛道应该做到第一梯队。

## 五、设计约束（你建议时不能违反）

1. **不能引入运行时堆**：任何建议都不能要求我在引擎内部 malloc/free。状态必须放调用方 buffer。
2. **不能破坏零耦合**：模块间不能直接 include 对方的 .c。如果某个优化需要模块间通信，必须通过 `include/zcsr/*.h` 契约头。
3. **不能引入 C++**：必须是纯 C11。
4. **不能为了性能牺牲自由度**：不能写死"只能做横版卷轴"或"最多 N 个敌人"。优化必须是通用的。
5. **平台层用官方框架**：macOS 用 Cocoa/NSOpenGL/AudioToolbox，Windows 用 Win32/WGL/winmm，不要自己重写底层。SIMD 用编译器内置（immintrin.h），不要手写汇编。
